# Техническое задание на развитие авторского журнала Дениса Михина

## 1. Контекст проекта

Сайт: https://media.dmikhin.ru/

Проект — авторский журнал и экспертная экосистема Дениса Михина.

Основное позиционирование:

**Денис Михин | Рост бизнеса через изменения**

Ключевая идея:
Денис Михин помогает компаниям находить точки роста, выстраивать системы управления, усиливать HR, проекты и процессы, внедрять современные управленческие подходы и технологии.

Сайт должен одновременно выполнять четыре функции:

1. Быть авторитетным экспертным источником по управлению, HR, проектному управлению, системному мышлению, Agile и применению ИИ в управлении.
2. Максимально хорошо индексироваться в Яндексе и других поисковых системах.
3. Быть понятным источником для AI-систем, которые извлекают и обобщают информацию из открытого интернета.
4. Конвертировать аудиторию в:
   - покупку курсов;
   - заказ HR по подписке;
   - заказ консультационных и трансформационных проектов;
   - узнаваемость и экспертный статус Дениса Михина.

## Что такое фрагментарное управление

> Фрагментарное управление — это модель, при которой подразделения оптимизируют собственные показатели без достаточной ответственности за сквозной результат бизнеса. В результате локальная эффективность может расти одновременно с увеличением потерь всей системы.

Этот блок должен:
- давать прямое определение;
- содержать 40–100 слов;
- отвечать на основной поисковый вопрос;
- не быть SEO-спамом;
- соответствовать смыслу самой статьи.

# 26. Search intent

При создании новых страниц сначала определять intent.

Типы:

### Informational
Пользователь хочет понять тему.

→ статьи / glossary / pillar pages.

### Commercial investigation
Пользователь выбирает решение.

→ экспертная коммерческая страница.

### Transactional
Пользователь готов заказать.

→ HR / консалтинг / курс.

Не смешивать все три intent на первом экране.

---

# 27. Обновление контента

На экспертных страницах отображать:

- дату публикации;
- дату последнего существенного обновления.

Не менять `dateModified` автоматически из-за технического деплоя.

Дата обновления должна меняться только при реальном содержательном изменении страницы.

# 28. AI-friendly контент

Основные требования:

- содержательный HTML;
- прямые определения;
- понятная структура H1/H2;
- короткие смысловые абзацы;
- таблицы только когда они действительно помогают;
- единый автор;
- канонические URL;
- связанные понятия;
- даты;
- ссылки на первичные источники;
- четкое отделение факта от авторской интерпретации.

Не пытаться манипулировать AI через скрытый текст.

Не использовать невидимые блоки ключевых слов.

Не создавать ложные «официальные определения».

# 36. Избегать каннибализации

- не конкурируют ли две страницы за один запрос;
- какая страница должна быть главной.

Если материалы дублируют intent:
- объединить;
- перенаправить;
- четко развести назначение.

# 45. Критерии готовности первого этапа

Этап считается готовым, если:

- существует индексируемая страница Дениса Михина;
- она является каноническим источником информации об авторе;
- все статьи ссылаются на нее;
- Person schema корректна;
- Article schema ссылается на Person;
- WebSite schema настроена;
- BreadcrumbList работает;
- sitemap содержит все важные страницы;
- robots не блокирует полезный контент;
- canonical корректен;
- на главной понятно, кто автор и о чем сайт;
- все важные тексты присутствуют в HTML, доступном поисковому роботу;
- не появились дубли URL;
- существующие статьи и их URL не сломаны.
